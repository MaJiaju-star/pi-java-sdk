# 客户端配置与生命周期

## 进程关系

一个 `PiClient` 对应一个 `pi --mode rpc` 子进程和一个活动 PI 会话。不要在多个业务用户之间共享同一个客户端；流式事件没有 prompt 请求 ID，无法安全拆分给多个并发调用者。

## 启动配置

```java
PiClientConfig config = PiClientConfig.builder()
        .executable("pi.cmd")
        .workingDirectory(Path.of("D:/workspace/project"))
        .provider("openai")
        .model("gpt-5.4")
        .sessionName("代码审查")
        .sessionDirectory(Path.of("D:/pi-sessions"))
        .noSession(false)
        .environment("OPENAI_API_KEY", token)
        .startupTimeout(Duration.ofSeconds(20))
        .requestTimeout(Duration.ofMinutes(5))
        .shutdownTimeout(Duration.ofSeconds(3))
        .build();
```

主要配置：

| 方法 | 作用 |
| --- | --- |
| `executable` | 指定 PI 可执行文件 |
| `command` | 指定完整启动前缀，例如 `node` 加源码 CLI 路径 |
| `workingDirectory` | PI 工具操作的工作目录，不是安全沙箱 |
| `environment` | 增加或覆盖子进程环境变量 |
| `argument` | 追加 PI CLI 参数 |
| `startupTimeout` | `get_state` 就绪探测超时 |
| `requestTimeout` | RPC 响应默认超时 |
| `maxJsonLineBytes` | 单条 JSONL 的字节上限 |
| `maxCapturedStderrChars` | 保留的 stderr 尾部字符数 |
| `eventBufferCapacity` | 待消费事件数量上限 |
| `eventOverflowStrategy` | 事件缓冲区满时的处理方式 |

SDK 自动追加 `--mode rpc`，`command` 中不要重复填写。

## 生命周期

```java
PiClient client = PiClient.start(config);
client.onExit().thenAccept(exit -> log.info(
        "PI 退出: code={}, expected={}", exit.exitCode(), exit.expected()));

PiClient replacement = client.restart();
```

`restart()` 返回新实例，旧实例的订阅不会复制。推荐使用 try-with-resources 确保关闭子进程。

## CLI 版本探测

```java
PiCliVersion version = PiCliVersion.detect(config);
System.out.println(version.semanticVersion().orElse(version.raw()));
```

SDK 当前验证版本记录在 `PiCliVersion.TESTED_VERSION`。版本不同不一定不兼容，但应运行集成测试。
