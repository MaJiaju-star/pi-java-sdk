# 错误处理、安全与反压

## 异常类型

| 异常 | 含义 |
| --- | --- |
| `PiRpcException` | PI 返回 `success: false` |
| `PiRequestTimeoutException` | 请求在配置时间内没有响应 |
| `PiProcessException` | 子进程启动、退出或 stdin 写入失败 |
| `PiProtocolException` | stdout 不是合法 UTF-8、JSONL 或响应关联失败 |
| `PiRemoteServerException` | 远程服务端返回结构化错误 |
| `PiRemoteException` | CBOR、传输、握手或远程协议失败 |

异步 API 的异常在 `CompletableFuture` 中传播。调用 `join()` 时通常包裹为 `CompletionException`，调用 `get()` 时包裹为 `ExecutionException`。

## 超时

默认 RPC 响应超时为五分钟：

```java
PiClientConfig.builder().requestTimeout(Duration.ofMinutes(2));
client.request("custom_command", Map.of(), Duration.ofSeconds(30));
```

请求超时不会自动中止 PI 正在进行的模型或 Bash 操作。需要停止副作用时同时调用 `abort()` 或 `abortBash()`。

## 事件反压

监听器运行在独立事件分发虚拟线程，不会直接占用 stdout 解析线程。缓冲区默认容纳 1024 个事件。

| 策略 | 行为 | 适用场景 |
| --- | --- | --- |
| `BLOCK` | 阻塞读取并通过管道向 PI 反压，不丢事件 | 默认、审计和完整 UI |
| `DROP_OLDEST` | 丢弃最旧事件 | 只关心最新进度的界面 |
| `DROP_LATEST` | 丢弃新事件 | 保留先到事件的诊断流程 |
| `FAIL` | 缓冲区满时终止客户端 | 不能接受丢失或阻塞的严格系统 |

丢弃策略可能丢失 Extension UI 请求，不适用于需要扩展交互的宿主。

## 安全边界

`workingDirectory` 不是沙箱。PI 默认工具可以读写文件并执行 Bash。服务端至少应实施：

- 每个租户独立目录或容器。
- 模型凭据不返回浏览器、不写入事件日志。
- 限制图片、prompt、JSONL、CBOR 帧和进程数量。
- 对 Extension UI 回复做会话归属检查。
- 审计工具调用，限制危险命令和网络出口。
