# 会话池与故障恢复

## 为什么需要进程池

问题：RPC 流事件通常没有 prompt 请求 ID。

例子：如果用户 A 和用户 B 同时复用一个 `PiClient`，服务端无法可靠判断文本 delta 属于哪个 HTTP 会话。

解决：每个业务对话使用独立 `PiClient`，由 `PiClientPool` 限制进程总数。

```java
PiClientConfig config = PiClientConfig.builder()
        .workingDirectory(Path.of("D:/workspace"))
        .noSession(true)
        .build();

try (PiClientPool pool = PiClientPool.fromConfig(20, config)) {
    PiClientPool.Entry entry = pool.create();
    PiClient client = entry.client();
    client.prompt("开始分析").settled().join();
    pool.remove(entry.id());
}
```

## API

```java
public final class PiClientPool implements AutoCloseable {
    public record Entry(String id, PiClient client) { }

    public PiClientPool(int maxClients, PiClientFactory factory)
    public static PiClientPool fromConfig(int maxClients, PiClientConfig config)

    public Entry create() throws IOException
    public PiClient getOrRecover(String id) throws IOException
    public PiClient recover(String id) throws IOException
    public PiClient require(String id)
    public List<Entry> entries()
    public boolean remove(String id)
    public void close()
}
```

| 方法 | 行为 |
| --- | --- |
| `fromConfig` | 所有客户端共享同一启动配置的池 |
| `create` | 启动新客户端并加入池，返回带随机 UUID 的 `Entry`；池满时抛 `IllegalStateException` |
| `getOrRecover` | 获取活动客户端，进程异常退出时用同一池 ID 自动创建替代实例 |
| `recover` | 替换已退出客户端；原客户端仍活动时直接返回原实例 |
| `require` | 获取指定 ID 的客户端，ID 不存在抛 `IllegalArgumentException` |
| `entries` | 当前池条目快照（后续变更不影响该列表） |
| `remove` | 移除并关闭客户端，找不到返回 `false` |
| `close` | 关闭全部客户端并清空池，重复调用安全 |

`PiClientFactory` 是函数式接口 `PiClient start() throws IOException`，自定义工厂可实现差异化启动逻辑。

## 异常退出

```java
client.onExit().thenAccept(exit -> {
    if (!exit.expected()) {
        alert(exit.exitCode(), exit.stderr());
    }
});
```

`PiProcessExit` 是 `record (int exitCode, boolean expected, String stderr)`。`expected=false` 表示非预期退出。

## 恢复

```java
PiClient recovered = pool.getOrRecover(poolId);
```

替代进程**不会自动恢复未落盘上下文，也不会复制旧事件监听器**。需要连续上下文时，应启用会话持久化，并在替代客户端中执行 `switchSession()`；监听器必须重新注册。

自动重放最后一个 prompt 不是默认行为，因为旧进程可能已执行部分写文件或 Bash 操作，重放可能造成重复副作用。
